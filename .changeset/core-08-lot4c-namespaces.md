**BREAKING** (0.8-internal) — one namespace contract (lot 4c). A namespace is active while the `namespaces` option names it or a component's `useI18n(ns)` holds it (counted per instance); `setLocale()` waits for the active set at its call, and once it applies, what the active set then lacks for the new locale loads (a component that mounted meanwhile ends with the new locale's catalog). With no component left the namespace stays cached and a switch skips it. `load(ns)` loads (and is the explicit retry of a failed load) without keeping the namespace active; releasing a namespace aborts and evicts nothing. `t()` and `i18n.ns()` only read: they never start a request, and in development a read of a namespace with no catalog for the locale, no consumer, no load in flight and no failed load warns once per instance and namespace, naming the fixes (0 B in production) — checked again after the render's task, so a `<T ns>` beside the `useI18n(ns)` that holds it at commit or mount does not warn, while a `useI18n(ns).t()` call with another `{ ns }` is checked as any read. A consumer is counted before its hold publishes anything, and a release called twice releases once. `handover()` hands over every namespace with a catalog of the chain in place — an inline one a server render read without a hold too, since the browser's `{ ...options, ...payload }` replaces its `catalogs` — and every namespace the instance needed (pinned, held or `load()`ed), whatever the consumers do later, a failed pair as `null`; the editor handle's `state().ns` lists the same set. A switch that rejects loads again what its start aborted for the locale kept on screen. `i18n.ready` is documented as what it is: it settles when the loads in flight settle, failed ones too, and says nothing about a namespace's catalog — the bindings' `isReady` does.
