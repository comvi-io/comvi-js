**Development build: the dev-only diagnostics now actually fire under a bundler's development condition.** The `IS_DEV`-guarded `<T raw>` deprecation was dead code in the published package. `__DEV__` is a build-time define of OUR build, `vite build` pins `NODE_ENV=production`, and the package published exactly ONE artifact, so the only file a consumer could resolve had `__DEV__: false` baked in no matter what mode the app built in. `dist/comvi-solid.dev.js` (and its `<T>` chunk) now ships alongside the production artifact, and `exports["."]` answers the `"development"` condition with it — the pattern `@comvi/core` already used for its readable error messages. A vite dev server, a `NODE_ENV=development` vite build and `webpack --mode development` resolve it and log the warning; every other consumer resolves `default` and gets the production artifact, which is byte-for-byte what it was — no row of the size gate moved, and `types` is unchanged and shared by both. The claim is gated on the DIST from now on: the bundler-matrix `solid-dev-conditions` case bundles a consumer that defines nothing, once per mode per bundler, and asserts the warning text is in the development bundle and out of the production one.
