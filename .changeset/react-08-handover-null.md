`<I18nHandover catalogs>` takes a server payload's failed slots (`HandoverCatalogs`: `Catalog | null`) with the meaning `createI18n({ catalogs })` gives them: the subtree renders without that catalog (the fallback the server rendered), and at commit the instance drops a catalog it held for the pair and does not ask for it until `i18n.load(ns)` or a switch to its locale. A later payload (a `router.refresh()`) therefore means what the first one meant; nothing remounts. A render with such a slot knows the load failed: translation, `isReady` and `isLoading` read the pair as failed, as the server did, even when the client already has a load of it in flight (the commit aborts that load) and below a nested `<I18nHandover>` whose own payload does not mention the pair. So a hydration through `<I18nHandover catalogs>` with a client loader takes the same branch as the server HTML (before, it rendered the loading branch and React reported a hydration mismatch). An explicit `i18n.load(ns)` or `setLocale()` still asks for the pair and shows its flight; a later payload with a catalog for the pair ends the failed state.
