`@comvi/core` is compiled with `useDefineForClassFields: false`. **−191 B min+gz on every entry**, no logic change, no source change — one tsconfig line.

TypeScript's ES2022 `[[Define]]` field semantics lower all 35 of `I18n`'s class fields through a `__publicField(this, …)` helper that runs before the constructor body. Every one of those fields is either assigned in the constructor anyway or `declare`d by a capability module, so the ceremony bought nothing and cost 541 minified bytes. Measured end to end through the published exports map at the commit this landed, under the entry names of the time (HISTORICAL — later changes in this same release moved every number; the current baselines live in `scripts/size-budgets.json`): the base host **5563 → 5372 B**, the fully composed graph **8519 → 8328 B**, base + tags 6410 → 6226 B, base + ICU 6434 → 6234 B, and every framework fixture −174…−200 B.

**Behavior is identical. Reflection is not, in exactly two ways** — relevant only if you enumerate or serialize an instance (devtools panels, structured loggers, snapshot serializers, `JSON.stringify` of the instance itself):

1. **A declared-but-unassigned field is no longer an own property.** With `[[Define]]` lowering, every declared field existed as an own property from construction, holding `undefined` until something wrote to it. Now a field becomes an own property when it is first assigned. The one PUBLIC member this is observable on is `instanceId`: an instance created with `exposeGlobal: false` (or constructed where there is no `window`, i.e. every server render) no longer has an `instanceId` key at all, where it previously had one whose value was `undefined`. `i18n.instanceId` still reads `undefined`, `Object.keys(i18n)` and `{ ...i18n }` no longer list it. The single-entry convergence in this same release narrows the point further: `instanceId` is assigned only by the devtools capability, so on a host that never composes it the key is simply never there.
2. **Own-property order is now assignment order**, not declaration order. For the public keys the two orders coincide — `translationCache`, `apiKey`, `collectContext`, `devMode`, then `instanceId` if discovery exposes the instance — so a consumer reading keys positionally sees the same sequence. Internal `_`-prefixed keys (TS-private, renamed by the property mangler in every published artifact, never a supported surface) may be ordered differently.

Nothing else about the reflective contract moved: every public method and accessor is still a non-enumerable prototype member with `{ writable: true, enumerable: false, configurable: true }`, prototype patching still intercepts instance calls, and a spread copy still carries data only. Both consequences above are pinned by `tests/root-contract.test.ts`, which now asserts the exposed and non-exposed shapes separately instead of one combined key list.
