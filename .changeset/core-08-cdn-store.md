`@comvi/core/cdn` gets a catalog store and an API loader. `createCatalogStore({ ttl })` (default 60 s) keeps what the loaders fetched, per URL: concurrent requests share one fetch, a caller that aborts stops waiting without cancelling it for the others, a catalog younger than `ttl` is answered without a request, and an older one is answered at once while one revalidation runs behind it — a conditional GET with `If-None-Match` when the response had a readable ETag. A 304 keeps the same catalog object, so its compiled messages survive the revalidation; a failed revalidation keeps the last good catalog. Pass one store per server process and create an instance per request: `cdn(base, { store })`. Without `store` nothing changes: every load is its own request and an abort cancels it (the store is not in a browser bundle that does not import it). `cdn(base, { fetch })` and `api(base, { fetch })` call the given `fetch` instead of the global one. `api(base, { key, store?, fetch?, timeout? })` reads the same catalogs from the platform API (`GET <base>/v1/translations?locales=<locale>&namespaces=<ns>` with `Authorization: Bearer <key>`) — for servers and scripts; a key in a browser bundle is readable by anyone. A signal that is already aborted is refused before any request, with or without a store. `api()` reads only the body's own properties (`namespaces[ns][locale]`) and fails with its own message when the body lacks the pair; in a store its catalogs are kept under the SHA-256 of the key, never the key, so no store holds the credential and two keys never share a catalog. A failed first fetch leaves nothing in the store. There is no default store yet: a loader without `store` makes its own requests.
