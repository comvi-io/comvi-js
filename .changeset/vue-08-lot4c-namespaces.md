`useI18n(ns)` returns `isReady` beside `isLoading` (computed refs over the core's predicates): `isReady` when a catalog of the locale on screen, its parent or an allowed fallback locale is in, `isLoading` while one loads or the component's hold will load one (once the component released it — unmount, `KeepAlive` deactivation — a load in flight only, and its `t` reads like `$t`, so a kept result or a deactivated component's watcher is never loading forever); a failed load is `false`/`false`. The component holds its namespace from mount to unmount; inside `<KeepAlive>` deactivation releases it and activation holds it again (mount + first activation hold once); `v-show` keeps it. On a server it is held for the request and loaded before the component renders, so a `v-if` on `isReady` takes the same branch in the hydration. With no component holding it, a switch does not load it. The exported `<T>` and `$t` read only: `<T ns>` no longer loads its namespace, in the browser or on a server (load it with `useI18n(ns)`, a route's `i18n.load(ns)` or the `namespaces` option); `useI18n(ns).T` reads the namespace its `useI18n` holds. `$t`'s idle-namespace warning is now the core's, shared by every reader. Outside a component (`app.runWithContext()`, a store, a router guard) `useI18n(ns)` registers no lifecycle hook in any build and holds nothing: its `isLoading` is a load in flight only, and its reads are checked like `$t`'s.
