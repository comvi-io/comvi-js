**BREAKING** — `i18n.setLocale(locale)` and `i18n.load(ns)` return `Promise<Error | undefined>`: they resolve with the failure, or with nothing, and no longer reject for a failed load or an invalid tag. `setLocale()` resolves with an `Error`, and keeps the old locale, when no namespace it waited for has a catalog of the locale's own chain (`de-AT`, or its parent `de`); `load(ns)` when the locale's own load of `ns` failed and no catalog of that chain is in place. The `Error` is the loader's own error when the loader rejected or threw with an `Error` (the same object); any other reason (a string, `undefined`, `null`, `0`) is wrapped in an `Error` whose `cause` is that reason. An invalid tag resolves with a `RangeError`. Every other call resolves `undefined`: switched, already there, a load a switch aborted, a fallback locale's or a parent's failure alone, a destroyed instance, and a call overtaken by a newer `setLocale()` (read `i18n.locale` for what is on screen). When the promise settles, what is published, what `onError` receives, `ready`, the readiness flags and the negative cache do not change. An ignored call raises no `unhandledrejection` for these outcomes, with or without `onError`; `onError` only reports. Write `const failure = await i18n.setLocale(code)` and test `failure !== undefined`; `failure` is truthy when the call failed. In a Vue Router guard, `() => i18n.load(ns)` hands the value to the router (a failure fails the navigation with that `Error`); `async () => { await i18n.load(ns); }` navigates either way. `setLocale` from `useI18n()` (React, Vue, Solid, Svelte) has the same type. The bindings act on the failure only: Vue's writable `locale` ref re-renders its readers when a switch fails (a write still never throws), `<I18nHandover locale>` of `@comvi/react` gives its target up when its switch is refused, `detect()` of `@comvi/core/plugins` falls back to the `locale` option when the detected locale fails; none does anything for an overtaken call. `@comvi/nuxt`'s route middleware follows `i18n.locale` after a switch as before, and its server `useTranslation()` renders the fallback after a failed load as before.
