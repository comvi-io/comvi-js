**BREAKING** (0.8-internal) — honest `t()` types and `<T components>`. Without generated catalogs, a `t()` call whose params are all text is typed `string`, and a call with a tag handler or a node param `string | VNodeArrayChildren` (it was typed `string`); an inline handler's argument is still inferred. `<T :components="{ b: 'strong', em: Emphasis, link: { component: RouterLink, props: { to: '/terms' } } }">` (the exported and the bound `<T>`) renders tags by name — an HTML tag name, a component, or `{ component, props }` for one that needs props of its own; the tag's content is its default slot — so nested markup renders without `h()`. A tag renders through, in this order, a handler attribute, its `components` entry, a slot of its name; an attribute or an entry that is `undefined` no longer hides the next (`null` still does: the tag renders as text). A slot's `children` is always the tag's text from the message, built before any nested handler runs: nested markup is flattened to text (`{{ children }}` never prints nodes) and development warns once to use `components`. No attribute falls through on either `<T>`: `class` and `style` are message params, and with generated catalogs vue-tsc reports a required param that a misspelt attribute left out.
