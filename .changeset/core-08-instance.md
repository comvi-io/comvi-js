**BREAKING** — `createI18n(options)` returns the 0.8 instance: synchronous construction (no `init()`), exactly thirteen members — `locale`, `dir`, `ready`, `t`, `ns`, `setLocale`, `load`, `add`, `has`, `on`, `rev`, `destroy`, `setDefaultParams` — over one immutable state that `on()` subscribers are told about on every change. Options: `locale`, `fallbackLocale` (one, a list, or lists per locale with a `default`), `messages` (the `default` namespace) and `catalogs` (by namespace), `loader(locale, ns, signal)`, `namespaces`, `defaultParams` (copied: each published state keeps its own), `plugins`, `timeZone`, `now`, `formats`, `onError`, `missing`. `t(key, { ns, locale, ...params })` switches namespace and locale per call (`ns` and `locale` are reserved names, never message params, read from the params object's own properties); an invalid per-call locale renders in the instance locale and is reported once per locale; `i18n.ns("shop")` binds a namespace (an empty one is `default`); the `"ns:key"` spelling is gone. A locale falls back through its parents (`pt-BR` → `pt`) and then `fallbackLocale`; an empty translation counts as missing. Catalogs are flat and kept by reference; `add()` over an existing catalog writes a patch layer instead of copying it, and adding messages the pair already renders — the same catalog, or a new object with the same values — changes and publishes nothing. An empty string added over a translation hides it: the key falls back to the next locale, as an empty translation does. Loads are deduplicated per locale and namespace, and `setLocale()` switches inside the call when nothing has to load, otherwise once its loads settle — a namespace that fails to load (a 404 for one file) no longer blocks the switch, nor does a missing regional file when its parent loads (`pt-BR.json` 404, `pt.json` 200); only a locale with no catalog of its own chain at all rejects. A missing parent is not a failure when the regional file loads (`pt.json` 404, `pt-BR.json` 200): a parent's failed load is reported as `load_failed` only when the locale's own load of that namespace failed too (a fallback locale's failure is always reported). A namespace loaded while a switch is pending is loaded for the new locale too. `load(ns)` publishes when `ns` joins the active namespaces, even with nothing to load. `defaultParams: {}` is no default params. `has(key, { fallback: false })` looks in the locale alone, neither its parents nor `fallbackLocale`. `ready` is one promise for as long as the set of loads in flight does not change. Malformed locales are reported as `invalid_locale` before anything renders or loads. Every problem is an `onError` report with a code: `missing_key`, `missing_param`, `syntax`, `load_failed`, `invalid_locale`, `fallback_used`. A key is not `missing_key` while its namespace is still coming: a load of it is in flight, or the instance has a loader and the namespace is not active yet and holds no catalog of the locale (a binding renders `useI18n(ns)` before it activates `ns`). An `onError` that throws never breaks a render or a load (its error is rethrown asynchronously). The default reporter prints each problem once per process in development — on a development SSR server, once for all requests. New subpaths: `@comvi/core/cdn` (`cdn(base)` reads the Comvi CDN exactly as `@comvi/plugin-fetch-loader`'s CDN loader did; `cdn(base, { fallback: { de: () => import("./locales/de.json") } })` serves bundled catalogs when the CDN cannot answer, never on an abort — a `fallback` returning a module (`import("./de.json")`) or the catalog itself both work, a catalog with a key named `default` included; `root: false` puts every namespace in its own folder), `@comvi/core/plugins` (`plugins: [detect({ supported })]` starts in the locale the URL, cookie, storage or browser names, before anything loads; `persist()` saves every switch), `@comvi/core/format` (`formatNumber`, `formatCurrency`, `formatDate`, `formatDateRange`, `formatRelativeTime(i18n, date, now?)`, `formatList`, `displayName`; `formatNumber`/`formatDate` take the name of a `formats` entry; a `locale` override that is not a locale formats in the instance locale chain) and `@comvi/core/devtools` (`plugins: [devtools()]` makes the instance discoverable by the Comvi browser extension, which loads the in-context editor on request). `@comvi/plugin-fetch-loader` and `@comvi/plugin-locale-detector` are replaced by `/cdn` and `/plugins` and get no 0.8 release: their last versions stay on npm, deprecated with a pointer to the subpath.
