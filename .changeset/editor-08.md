**BREAKING** — the in-context editor is now `@comvi/editor`, and it is only a script the Comvi browser extension loads. `@comvi/plugin-in-context-editor` gets no 0.8 version. For a 0.7 user: remove `@comvi/plugin-in-context-editor` from the app, compose `plugins: [devtools()]` from `@comvi/core/devtools` on the instance, and open the editor with the extension; no API key goes into the app. There is no npm or plugin mode any more: `inContextEditor()`, `inContextEditorPlugin()`, `.use(…)`, the production stub, `init()`/`stop()`, the encoder exports and `i18n.apiKey` are gone. The package ships one file, `dist/standalone.iife.js`, which `x.load(version)` of the instance's handle puts on the page from jsDelivr; it sets `window.ComviInContextEditor` with `activate(options)`, `deactivate()`, `isActive()` and `version`. `activate({ apiKey } | { transport, apiBaseUrl }, …)` returns `{ ok: true, stop, collectContext: false }`, or `{ ok: false, code, message }` with `code` one of `no-window`, `already-active`, `no-instance`, `old-protocol`, `unknown-protocol` — on such a page it does nothing at all: `window.__COMVI__` and its entries stay as they were and nothing is added to the page. The editor works on core 0.8 (protocol 2) only and marks every compatible instance on the page. Translations carry self-contained markers: a frame of invisible tag characters (`U+E007E` … `U+E007F`) names its instance, namespace and key itself, so text ending in ZWSP, ZWNJ or ZWJ (Thai, Persian, emoji sequences) stays editable and its preview keeps those characters, and two instances with the same key no longer mix; rich output is marked with a pair around its parts. Markers are not removed from strings the app sends elsewhere (titles, the clipboard, forms). A save goes to the platform for every language of the form, and changes the page only for the languages whose catalog loaded: a language that failed, is still loading or never loaded keeps its own load. This version collects no context: it makes no request to the context routes, so the platform gets no usage context for translations; the `collectContext` and `screenGroupResolver` options are gone.
