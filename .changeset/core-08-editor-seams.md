**BREAKING** — the in-context editor's seams for 0.8 (protocol 2). `plugins: [devtools()]` (`@comvi/core/devtools`, no options) is the only way an instance reaches the editor, through the Comvi browser extension: it pushes one entry `{ v, i, x }` onto `window.__COMVI__` and removes it on `destroy()`, where `x` is the handle the editor drives the instance through (`p: 2`, `kind: "comvi"`, `read`, `state`, `mark`, `load`). `x.load(version?)` takes an exact editor version or `latest`, never a URL, and resolves with the editor once it is on the page; anything it cannot do rejects, it never throws. Gone with the 0.7 hook: the `instanceId` on the instance and the `instanceId` / `exposeGlobal` / `editorVersion` options, the `Symbol.for("comvi.devtools.editorLoader")` slot, the v1 registry and hook probes, and the editor-mappings bridge of `@comvi/core/internal` (`EDITOR_MAPPINGS_GLOBAL`, `readEditorMappings`, …); the extension handles CSP diagnostics, timeouts and version choice itself, so the extension release that speaks protocol 2 is required. Translations are marked for the editor only while an editor session is active, found and missing keys alike; `t(key, { markers: false })` and `<T markers={false}>` opt one message out (`markers`, like `ns` and `locale`, is a reserved per-call option, not a message param). An instance without `devtools()` is never marked, and without a session `t()` takes no extra step. `add()` while a load of the same locale and namespace is in flight no longer cancels the load: the loaded catalog lands under the added messages, so they still win.
