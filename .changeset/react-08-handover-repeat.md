`<I18nHandover catalogs locale>` now treats a server payload the same way on every render. A slot this handover handed over before, in any earlier payload on the same instance, becomes the new catalog: a key the server no longer has is gone, and an empty catalog empties the slot. A slot it hands over for the first time is still layered over what the instance had, and `add()` is still a patch. A `null` slot fails the pair and aborts a load of that pair in flight, so a late answer cannot restore the catalog. The handover's own locale switch keeps the failures the payload brought and lands on the payload's locale through the fallback the server rendered, as a first payload does (a load that failed in the browser still keeps the instance's locale), while `setLocale()` and `load(ns)` still ask for them again. The core's internal seam does this; there is no new public API. With no binding registered, a rich-text `Tag` handler's argument is now typed as the rich parts the core passes (`RichParts`), not `any`. A `load(ns)` that a payload's `null` cuts off rejects with an `Error`. A server render through the handover reports a nested catalog's `syntax` events once per catalog object.
