`<I18nHandover catalogs locale>` follows one rule for a server payload: a slot it hands over fully replaces the instance's slot, the first time and every later time. A key the server no longer has is gone, an empty catalog empties the slot, and `null` is a load that failed on the server (the subtree renders the server's fallback). A slot the payload leaves out is not changed, and `add()` is still a patch. With two handovers on one instance, the last payload applied wins per slot. This replaces the earlier layering of a first-time slot over a catalog the instance already had. A `null` aborts a load of that pair in flight, so a late answer cannot restore the catalog; a `load(ns)` it cuts off rejects with an `Error`. The handover's own locale switch decides from the current payload only: a pair it carries as `null` is not asked for again, and the switch lands through the fallback the server rendered, as a fresh mount does; any other failure of the target is retried as `setLocale()` retries it. `setLocale()` and `load(ns)` keep their contract. The core's internal seam does this; there is no new public API. With no binding registered, a rich-text `Tag` handler's argument is now typed as the rich parts the core passes (`RichParts`), not `any`. A server render through the handover reports a nested catalog's `syntax` events once per catalog object.
