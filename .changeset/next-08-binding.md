**BREAKING** — `@comvi/next` is rebuilt on the 0.8 core and `@comvi/react`, both now peer dependencies the app installs (`npm install @comvi/next @comvi/react @comvi/core`), App Router only (Next 15.5.28+ and 16.4.3+, React 19.3.1+). `createGetI18n({ locales, defaultLocale, timeZone, loader?, ...options })` from `@comvi/next/server` returns the app's `getI18n({ locale?, ns? })`: an instance per request (React `cache()`, per locale and namespace set), its namespaces loaded before it resolves, each (locale, namespace) loaded once per request and a failed one kept failed for the request; nothing is shared between requests. The locale is matched against `locales` before any instance exists (any other is `notFound()`); an explicit locale reads no request API, so a static page stays static and a page does not depend on its layout having rendered first; without one, the middleware's header, else `defaultLocale`. It returns `t` (bound to the first namespace, rich text joined into one React node), `locale`, `dir` and the instance. The server `<I18nProvider i18n routing? client?>` from `@comvi/next/server` hands the browser `handover(i18n)` and the instance's `fallbackLocale`, `formats` and current `defaultParams` (`ClientSettings`), nothing else — not the loader, callbacks or other options; `client` is an app's `"use client"` component that adds a browser loader, `onError` or `plugins`. `@comvi/core/ssr` with the client provider stays the manual path. `<I18nProvider payload options? routing? loading? suspense?>` from `@comvi/next/client` creates the browser instance once per mount from `{ ...options, ...payload }` (a slot that failed on the server stays failed) and hands a later payload of the same mount over through `<I18nHandover>` with the same meaning (a catalog that fails on a `router.refresh()` renders the server's fallback; nothing remounts); a page that needs more namespaces than its layout renders its own provider. Client Components read through `@comvi/react`. Switching a localized route is a navigation (`@comvi/next/navigation`); `/routing`, `/navigation`, `/middleware` and `/proxy` are unchanged. `withComvi()` keeps the shape of the config it wraps. Removed with the 0.7 core: the package root and its re-exports, `@comvi/next/config` and `withComvi({ config })`, `createNextI18n`, `createNextI18nFromInstance`, `setI18n`, `setRequestLocale`, `getLocale`, `loadMessages`, `<ComviProvider>`, `nextPlugin`, `nextPluginLazy`, the hooks and core re-exported from `/client` and `/server`, and the provider's `i18n`, `locale`, `messages` and `autoInit` props.
