**`<I18nProvider fallback>` gates the first paint.** Neither provider used to gate it, each README prescribed a different loading gate, and every CDN quickstart as written painted raw keys once before the catalog arrived. `fallback` — `ReactNode` in react, `JSX.Element` in solid — renders instead of the children until the host is INITIALIZED, and the children replace it when initialization finishes. The axis is `isInitialized` (the same host state `useI18n().isInitialized` reads), deliberately not `isInitializing`: `init()` starts from an effect, after the first render, so a gate on "is it initializing" is open for exactly the frame the raw keys would paint in. With `autoInit: false` the gate therefore holds until the app calls `i18n.init()` itself. Both branches render inside the provider, so the fallback may use the hooks. React's server snapshot keeps its contract — `ssrInitialIsInitializing` is `false` by default, so a server render is never gated and the hydration render reads that same snapshot; solid has no such snapshot, so `renderToString` (where no effect runs) paints the fallback, hydrates it consistently, and swaps once the client host initializes. Purely additive — omit the prop and the rendered tree is what it was. Svelte has no provider component and vue's equivalent is a `<Suspense>`-shaped question; both document the three-line `{#if $isInitializing}` / `v-if="isInitializing"` gate in their README instead of growing an API, which is sound there because both start init synchronously before the first paint.
