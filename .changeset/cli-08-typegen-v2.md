**BREAKING** — `comvi typegen` writes the 0.8 declaration: `interface Catalogs` of the module the app declares, one member per namespace, each key's params directly (a tag is a `Tag` param, a `select` its options, a `plural` count a `number`), through the same generator as `@comvi/vite-plugin`, so both write the same bytes for the same catalogs. From the platform it reads the typegen schema v2 (`GET /v1/projects/:id/schema/v2`, scope `schema:read`); `--watch` takes the v1 schema stream as its change signal and fetches v2 on each event. New: `--from <dir>` generates from local JSON catalogs and `--from .comvi/schema.json` from the schema `comvi pull` now writes (`--no-schema` skips it; a key without `schema:read` or a platform without the route only skips it, with a warning), both offline with no key; `--out`, `--source-locale`; `defaultParams` in `.comvirc.json` (the params `createI18n({ defaultParams })` fills become optional). An unchanged declaration is not rewritten, and a second `--watch` of the same file waits while the first writes. `--check` exits 1 on an outdated file, 4 for broken catalogs or a schema the declaration cannot express (a param named `ns`, `locale` or `markers`), and never calls an unreadable file outdated. `comvi check` reads messages with `@comvi/core`'s own scanner: a message core cannot compile (an unclosed or unmatched tag, a select without `other`) is a `syntax` error, which replaces the `unbalancedTags` warning (`--format json` is version 2); ICU's number syntax in `=N` selectors (`=1e3`, `=.5`, `=+1`) is accepted, as core accepts it. Removed: `TranslationKeys` output and its `"ns:key"` keys, `strictParams` (config and `init --no-strict-params`), `TypeGenerator`, `TypeEmitter`, `FileSystemWriter`/`NodeFileSystem`/`InMemoryFileSystem`, the generation reporters, `ApiClient.fetchSchema`/`subscribeToSchemaUpdates` and the `eventsource` dependency. `generate()` and `watch()` are exported for programmatic use.
