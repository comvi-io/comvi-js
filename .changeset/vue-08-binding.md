**BREAKING** — `@comvi/vue` is rebuilt on the 0.8 core. `createI18n(options)` makes core's instance and makes it a Vue plugin: `createApp(App).use(i18n)` provides it to every component and sets the global `$t` (typed by generated catalogs through `ComponentCustomProperties`). `useI18n(ns?)` returns `t`, `T`, `locale`, `dir`, `isLoading`, `setLocale` and the instance: `locale` is a writable computed ref (setting it switches; it keeps the old value until the new locale's catalogs are in, and a failed switch is reported through `onError`, never thrown at a `v-model`), `dir` and `isLoading` are computed refs, and a component that reads only the locale does not re-render when a namespace loads. `ns` binds `t` and `T` (one component per instance and namespace; an `ns` attribute never re-targets it) and is loaded after the component mounts, never during setup or render (with a loader, its first render already shows it loading and reports no `missing_key`); a remount does not fetch a namespace whose load failed again (`i18n.load(ns)` retries). `<T i18n-key ns? locale? markers? {...params}>` renders a message: a tag's handler is a slot of the tag's name (`<template #link="{ children }">`, `children` is the tag's text) or an attribute (`:link="(c) => h('a', c)"`, for a tag that holds markup — it gets the list of its parts); attribute names are camelized as Vue camelizes props, so `:first-name` fills `{firstName}`; `<T ns>` loads that namespace after it mounts. `useFormat()` from `@comvi/vue/format` formats numbers, currency, dates, ranges, lists, display names and relative time in the locale on screen, re-rendering on a switch. A server render activates nothing: the request creates its own instance with the app, loads its route's namespaces and awaits `i18n.ready`; `handover(i18n)` returns the locale, `timeZone`, clock and catalogs it rendered with, and `createI18n({ ...options, ...payload })` in the browser hydrates without a mismatch and requests none of them. The peer range is `vue ^3.5.0`. Removed with the 0.7 core: `createI18nFromCore`, the `.use()` composition and the capability re-exports (`icuCompiler`, `loader`, `attachLoader`, `plugins`, `devtools` — pass `loader` and `plugins` to `createI18n`), `useI18nLoader` (→ `i18n.load(ns)`), `isInitializing` (mount after `i18n.ready`), `loadedLocales`, `activeNamespaces`, `tRaw`, `hasTranslation` (→ `i18n.has`), the formatters on `useI18n()` (→ `@comvi/vue/format`) and `<T :components>` (→ slots and handler attributes). A development build (`development` export condition) explains a composable used outside an app that installed the instance, an instance installed into a second app on a server, and a server render of an instance with no `timeZone`; the production build ships no diagnostic text.
