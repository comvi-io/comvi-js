`comvi.types: { from, out?, sourceLocale?, fileTemplate?, augment? }` in `nuxt.config` writes the typed-translations declaration from local JSON catalogs (or `.comvi/schema.json`) through the same generator as `comvi typegen --from`, `@comvi/vite-plugin` and `withComvi({ types })`, byte for byte. `from` and `out` resolve against `rootDir`; `sourceLocale` defaults to `defaultLocale`; the file goes to `.nuxt/types/comvi.d.ts` (Nuxt's `typesDir`, where its tsconfigs are, also when a production build builds elsewhere) and the module adds it to Nuxt's generated tsconfigs (the app's and Nitro's), so `.vue` files and server routes are typed with nothing to configure or commit. `nuxt prepare`, `nuxt typecheck` and `nuxt build` generate it before anything is checked and fail on a broken catalog; `nuxt dev` follows the catalogs with one watcher until Nuxt closes, reports an error (a broken catalog, or a settings error such as an invalid `augment`) and keeps the previous file. Without `types`, nothing is generated. `comvi.types` needs Nuxt 3.21.11+ or 4.6.0+: on an older Nuxt the module's setup fails with an error that names the installed version (without `comvi.types` the module runs on `^3.7.0 || ^4.0.0` as before). The package now has a top-level `types`, so its types resolve under `moduleResolution: "Node"`, which Nuxt 3.7 to 3.9 use by default.
