"@comvi/core": minor
---

From 0.8 on, an instance that this copy of `@comvi/core` did not create fails at once with an error that names both versions, in the production build too: a binding (or `handover()`) that resolves one copy while the app created its instance with another throws `two copies of @comvi/core: <the instance's version>, <the reading copy's version>`. The instance's version is `undefined` when it comes from a core older than 0.8 (or is no instance at all); production used to return nothing there and fail later on an `undefined`. The development build says it in a sentence: for two versions it names both; for one version it also names a copy or a Proxy of the instance (pass the instance itself; in Vue, `toRaw()` it) and the development and production builds of one install; for an instance without a version it says the instance is none, or one of a core older than 0.8. `@comvi/core/format`'s formatters and a binding's `useFormat` clock throw the same error; in production an object that is no instance is that `Error` (with `undefined` as its version), no longer a `TypeError` with the message `i18n`. An instance carries the version of the core that made it under `Symbol.for("comvi")`. `@comvi/core` and every binding in an app must be on one version.
