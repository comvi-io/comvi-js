**BREAKING** — `@comvi/nuxt` is rebuilt on the 0.8 core and `@comvi/vue` (Nuxt 3.21.0+ on Node 22.20.0+; Nuxt 4.6.0+ on the Node it requires, verified on 22.22.3 and 24.x). One set of settings: the data go to `comvi` in `nuxt.config` (`locales`, `defaultLocale`, `localePrefix`, `localeCookie`, `localeDetection`, `head`, and now `timeZone` (required: a build error names it), `fallbackLocale`, `namespaces`, `formats`, `messages`); the functions go to `comvi.i18n.ts`, whose default export changes from an instance factory to `defineI18nOptions((event) => ({ loader, onError, missing, plugins }))` from `@comvi/nuxt/i18n` — called with the request's H3 event on a server and `undefined` in the browser, so one loader serves the server render, the browser and Nitro routes (`event?.$fetch ?? $fetch` forwards the user's cookies to an app route). The module creates the instance: on a server one per request, in the locale resolved from the request before it exists; it waits for the page's namespaces and hands the first render over in the Nuxt payload once, and the browser starts from it, so hydration asks the loader for nothing (a catalog the server failed stays failed until an explicit `i18n.load(ns)`). Later namespaces come from the browser's loader. `fallbackLocale` applies only when set (0.7 fell back to `defaultLocale`); `messages` is the `default` namespace by locale, nested or flat, compiled into the app bundle; a flat inline catalog is left out of every page payload (a nested one, or one a server `add()` changed, is handed over). The route middleware drives the instance from the route (the old locale stays until the new catalogs are in; a switch that fails keeps the locale on screen and its URL); `setLocale()` changes the text and the cookie, not the URL. `useI18n()`, `useFormat()`, `<T>` and `$t` are `@comvi/vue`'s own; `$i18n` is the instance. `@comvi/nuxt/i18n` exports `defineI18nOptions`, `cdn`, `api`, `createCatalogStore`, `devtools` and the `@comvi/core/format` functions. In Nitro routes `await useTranslation(event, { ns?, locale? })` gives `{ t, locale, dir, i18n }`, one instance per request and locale; every server instance is destroyed when its request ends (after the response, on a thrown handler, or when the client goes away), and its loads in flight are aborted. `routeRules` with `swr` are not supported. The server-source recipe's loader marks its catalog request with the header `x-comvi-catalog`; a page render that carries it (the route is missing) answers 404, so the load fails instead of rendering a page whose loader asks again. The header is reserved: a request carrying it to a page URL answers 404. Routing, `<NuxtLinkLocale>`, `useLocalePath`, `useSwitchLocalePath`, `useLocaleRoute`, `useRouteConfig` and `useLocaleHead` are unchanged. Removed: the module options `defaultParams`, `setup` (`comvi.setup.ts` and `@comvi/nuxt/setup`), `apiKey`, `ns` (now `namespaces`), `defaultNs`, `icu` and `basicHtmlTags`; the `useI18n()` members `defaultParams`, `setDefaultParams`, `tRaw`, `isInitializing`, `isInitialized`, `messagesCache`, `cacheRevision`, `loadedLocales`, `activeNamespaces`, `defaultNamespace`, `clearMessages`, `hasLocale`, `addMessages` (`i18n.add`), `hasTranslation` (`i18n.has`), `setFallbackLocale`, `on`, `reportError`, `formatNumber`, `formatDate`, `formatCurrency`, `formatRelativeTime` (`useFormat()`), `locales` and `defaultLocale` (`useRouteConfig()`); `useI18nLoader`, `useI18nPlugins` and the auto-imported formatters; from `@comvi/nuxt/i18n` `createI18n`, `icuCompiler`, `loader`, `attachLoader`, `definePlugin`, `plugins` and `defineComviI18n`; the Nitro utilities `loadMessages`, `getRequestI18n` and `getServerRuntimeConfig`, and `hasTranslation` of `useTranslation`; the app config `comvi.routing` and the private runtime config `comvi.apiKey`; the root types of those mechanisms: `NuxtI18nSetup`, `NuxtI18nSetupContext`, `NuxtI18nSetupNuxtApp`, `NuxtI18nSetupEvent`, `NuxtI18nSetupRuntimeConfig`, `CheckedNuxtI18nSetup`, `NuxtInstanceFactory`, `NuxtInstanceFactoryOptions`, `ComviNuxtInstanceRegistry`, `ResolvedNuxtInstance`, `RegisteredNuxtInstance`, `NuxtServerInstance`, `NuxtServerLoaderInstance`, `NuxtDefaultTranslationParams`, `NuxtI18nPrivateRuntimeConfig`, `ResolvedRoutingConfig`, `TranslationParams`, `TranslationResult`, `TranslationKeys`, `I18nLoaderApi`, `LoaderFn` and `MessagesMap`. New root types: `NuxtI18nFileOptions` and `I18nOptionsFactory`.
