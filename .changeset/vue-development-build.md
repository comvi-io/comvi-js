**Development build: the dev-only diagnostics now actually fire under a bundler's development condition.** Both `IS_DEV`-guarded warnings this package ships — the `<T raw>` deprecation and the late-compose warning `VueI18n.use` logs when a capability is composed after `app.use(i18n)` has started `init()` — were dead code in the published package; the late-compose one has been dead since it was written. `__DEV__` is a build-time define of OUR build, `vite build` pins `NODE_ENV=production`, and the package published exactly ONE artifact, so the only file a consumer could resolve had `__DEV__: false` baked in no matter what mode the app built in. `dist/comvi-vue.dev.js` (and its `<T>` / `keys` chunks) now ships alongside the production artifact, and `exports["."]` answers the `"development"` condition with it — the pattern `@comvi/core` already used for its readable error messages. A vite dev server, a `NODE_ENV=development` vite build and `webpack --mode development` resolve it and log the warnings; every other consumer resolves `default` and gets the production artifact, which is byte-for-byte what it was — no row of the size gate moved, and `types` is unchanged and shared by both. The claim is gated on the DIST from now on: the bundler-matrix `vue-dev-conditions` case bundles a consumer that defines nothing, once per mode per bundler, and asserts the warning text is in the development bundle and out of the production one.
