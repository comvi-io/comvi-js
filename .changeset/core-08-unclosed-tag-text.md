An opening tag that is never closed renders as its own text instead of failing the whole message: `a<br>b` renders `a<br>b` (as text; HTML is never executed), where it rendered the key and reported `syntax`. Only the tag's token becomes text; the rest of the message reads as always, so `a<b>{name}` still fills `{name}`. A closing tag closes the nearest open tag of its name within its sub-message, and the tags opened after that one become text: `<b>a<br>b</b>` is tag `b` with the text `a<br>b`. A closing tag that closes nothing (`a<b>x</i>`, `<b><i>x</b></i>`, a `</b>` outside the plural branch its `<b>` is in) is still a `syntax` error that renders the key. In development each never-closed tag gets one `console.warn` when the message compiles (`<br>` with the hint to write `<br/>`); production gives no signal and `onError` is not called. A message more than 200 levels deep (plural, select and selectordinal sub-messages and closed tags; a never-closed tag adds none) is now a `syntax` error that renders the key, instead of a `RangeError` thrown out of `t()`. Generated types list only the tags a message closes.
