`handover(i18n)` on `@comvi/core/internal` (re-exported by `@comvi/vue`): what a server render gives the browser — the locale, `timeZone`, the clock (`serverNow`) and every catalog the instance has in place — inline, loaded or `add()`ed, of every locale, so a translation the server rendered through a per-call `{ locale }` (its parents and fallback locales too) survives the hydration — in the shape of `createI18n({ catalogs })`; every slot whose load failed is handed over as `null`, so the browser renders the fallback the server rendered and does not ask for it while it hydrates; an explicit `i18n.load(ns)` (or a switch to that locale) asks for it again. `createI18n({ catalogs })` takes such a `null` slot. A development build throws when the instance has no `timeZone`. On a server (no `document`), an instance without a `now` option reads the clock once and keeps that reading: `formatRelativeTime` and `handover()` count from the same instant, so the browser formats what the server formatted. The component types `TComponentFor` and `BoundTFor` take an optional flag that makes `Tag` params optional props, for a binding whose `<T>` also takes a tag handler from a slot (Vue); the typo guard is the same. `messages` and `catalogs` together merge by locale: a `default` slot of a locale that `catalogs` carries (a `null` failed slot too) is the `catalogs` one, so `createI18n({ ...options, ...payload })` with inline `messages` keeps the server's catalogs and asks for none of them. The payload therefore grows with every catalog the server instance holds, inline catalogs the client also bundles included (they are sent again); and a handed-over slot replaces the client's slot of that namespace and locale whole, so keys only the client's inline catalog had are not restored during the page's life (no refresh in 0.8) — only `add()` or a new page load brings them back.
