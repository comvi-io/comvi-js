The server `<I18nProvider>` hands the browser the request instance's current `defaultParams`, so Server and Client Components render the same text. Only strings, finite numbers, booleans and `null` cross: any other value (a tag handler, an object, an array, a `Date`, `undefined`, `NaN`, `Infinity`) throws a `TypeError` at the server provider that names the param (`defaultParams.link`); give such a handler in a Client Component. A later payload (`router.refresh()`) that changes or clears them is one snapshot with its catalogs: `<I18nHandover defaultParams>` (new prop, `@comvi/react`) renders the subtree with them at once, so a component mounted in that render reads the new text with the new params, and the instance takes them at commit (`setDefaultParams()`) when they differ by value; nothing remounts. Explicit `t()` params still win. An app's client component that adds its own defaults (a tag handler, any value) passes one `options.defaultParams` object, and for a key both set the value in that object wins; client-only values stay in the browser and are never serialized. The rule of `<I18nHandover defaultParams>`: not passed, the instance's set is never changed; passed, the object replaces the whole set (`setDefaultParams()`), and `{}` clears it, so a later set may overwrite values and handlers the client set itself. The same set object again (a rerender with the same payload) does nothing, so changes the client made since stay; a new object is a new payload and overwrites them, even with the earlier values, but publishes nothing when it has the same own keys and values (`Object.is`) as the instance's current set, so an inline literal of plain values does not re-render anything. A value created anew on every render (an inline tag handler) is applied on every render, and in a component that reads `useI18n()` itself that loops: define it once. Own keys only; an own key named `__proto__` is a param like any other.
