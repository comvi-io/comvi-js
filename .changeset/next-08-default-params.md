The server `<I18nProvider>` hands the browser the request instance's current `defaultParams`, so Server and Client Components render the same text. Only strings, finite numbers, booleans and `null` cross: any other value (a tag handler, an object, an array, a `Date`, `undefined`, `NaN`, `Infinity`) throws a `TypeError` at the server provider that names the param (`defaultParams.link`); give such a handler in a Client Component. A later payload (`router.refresh()`) that changes or clears them is one snapshot with its catalogs: `<I18nHandover defaultParams>` (new prop, `@comvi/react`) renders the subtree with them at once, so a component mounted in that render reads the new text with the new params, and the instance takes them at commit (`setDefaultParams()`) when they differ by value; nothing remounts. Explicit `t()` params still win. An app's client component that adds its own defaults (a tag handler, any value) passes one `options.defaultParams` object, and for a key both set the value in that object wins; only its string, number, boolean and `null` values are compared, so client-only values are never serialized. The core's `defaultParams` accepts any value, as before.
