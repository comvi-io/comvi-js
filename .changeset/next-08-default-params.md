The server `<I18nProvider>` hands the browser the request instance's current `defaultParams`, so Server and Client Components render the same text. `defaultParams` on the SSR surfaces hold server data only: strings, finite numbers, booleans and `null`, in `createGetI18n()`'s configuration, in the client provider's `options` and in `<I18nHandover defaultParams>` (new prop, `@comvi/react`). Anything else (a tag handler, an object, an array, a `Date`, `undefined`, `NaN`, `Infinity`) is a type error, and a `TypeError` that names the key (`defaultParams.link`) where it is given; one check serves every surface. A tag handler goes with the translation instead: its params (`t("terms", { link })`) or `components` of `<T>`, on the server and in the browser. This is a deliberate change of the unreleased contract: the recipe of adding a client handler on top of the server's defaults in `options.defaultParams` is gone. The core's own `defaultParams` and `setDefaultParams()` take any value, as before.

A later payload (`router.refresh()`) is one snapshot with its catalogs: its set replaces the browser's whole set (`{}` clears it) — a component mounted in that render reads the new text with the new params, and the instance takes them at commit; nothing remounts. The same set object again (a rerender with the same payload) does nothing, so changes the browser made since stay; a new object is a new payload and overwrites them, even with the earlier values, but publishes nothing when it has the same own keys and values (`Object.is`) as the instance's current set. Explicit `t()` params still win. Own keys only; an own key named `__proto__` is a param like any other.
