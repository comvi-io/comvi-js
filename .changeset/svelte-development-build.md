**Development build: the `<T raw>` deprecation now actually fires under a bundler's development condition — and its text no longer ships to production.** The warning was doubly dead. `svelte-package` copies `src/` to `dist/` and substitutes no build-time defines, so `dist/T.svelte` shipped its guard as the literal source text `typeof __DEV__ !== 'undefined' && __DEV__`; no consumer defines `__DEV__`, so the warning was unreachable in development — while the un-foldable guard meant the message string, the dedupe `WeakSet` and the whole branch were retained in production bundles instead.

A `"development"` export condition cannot fix this: `dist/T.svelte` is reached RELATIVELY from `dist/index.js`, so a condition on the package root cannot switch it. The warning therefore moved to `#dev-warn`, a package `imports` entry — resolved by Node, webpack, vite/rollup and esbuild alike — whose `development` branch is the real implementation (`dist/dev-warn.dev.js`) and whose `default` branch is a no-op that does not contain the message at all. A vite dev server, a `NODE_ENV=development` vite build and `webpack --mode development` log the warning once per host; every other consumer gets the no-op, and the production graph is 114 B (min+gz) lighter than before for it. Public API, exports map, `sideEffects` and types are unchanged. The claim is gated on the DIST from now on: `tests/exports-smoke.test.ts` asserts the `imports` map's shape and condition ORDER plus which half carries the text, and the bundler-matrix `svelte-dev-conditions` case bundles a consumer that defines nothing, once per mode, and asserts the warning text is in the development bundle and out of the production one.
