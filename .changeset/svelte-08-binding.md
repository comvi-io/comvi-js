**BREAKING** — `@comvi/svelte` is rebuilt on the 0.8 core, with runes. `setI18n(i18n)` (replaces `setI18nContext`) makes the instance available below the component; it starts nothing, so `await i18n.ready` before `mount()` or read `isReady`. `useI18n(ns?)` returns `t`, `T`, `locale`, `dir`, `isReady`, `isLoading`, `setLocale` and the instance: `locale`, `dir`, `isReady` and `isLoading` are getters over one `$state.raw` per instance, so read them through the object (`r.locale`); destructured in a `<script>`, one is read once. There are no stores: `t` is a function that a template or a `$derived` re-runs on a new state (`{t("hi")}`, not `{$t("hi")}`). `t` returns a string always: a tag handler's output is joined into it, and rich text is `<T>`'s. `ns` binds `t` and `T` (one wrapper per namespace; an `ns` prop never re-targets it) and is held from mount to destroy, on a server inline for the request (a server render is synchronous: a route preloads with `await i18n.load(ns)`, else the namespace renders its loading branch); a remount does not fetch a namespace whose load failed again (`i18n.load(ns)` retries). `<T i18nKey ns? locale? markers? components? {...params}>`: a tag renders through its `components` entry (a tag name, a component, or `{ component, props }`, nested tags render too), or a snippet of its name (`{#snippet link(children)}`, `children` is the tag's text, development warns when markup is flattened). `<T components={{ br: "br" }}>` renders a real `<br>` for `<br/>` and `<br></br>`, on the client and on the server; an empty tag passes no children to a component. `<T ns>` reads that namespace and loads nothing. `useFormat()` from `@comvi/svelte/format` passes the real instance and the locale read at each call to the `@comvi/core/format` formatters, so what calls one re-runs on a switch; `@comvi/svelte/format` no longer re-exports the formatters. `handover(i18n)` returns what a server render hands the browser: `createI18n({ ...options, ...payload })`. Removed with the 0.7 core: `setI18nContext` and its `autoInit` / `onError` options, `useI18nInstance` (→ `useI18n().i18n`), `useI18nLoader` (→ `useI18n(ns)`, `i18n.load(ns)`), `useI18nPlugins`, the seven `create*Store` stores, `tRaw`, `isInitializing`, `isInitialized`, `cacheRevision`, `defaultParams`, the instance-method pass-throughs and bound formatters on `useI18n()`, the root re-exports of `icuCompiler`, `attachLoader`, `loader`, `definePlugin`, `plugins`, `devtools` and the formatters, and `<T>`'s `params`, `fallback` and fallback children. A development build (`development` export condition, through `esm-env`, a new dependency Svelte itself depends on) explains a component with no `setI18n` above it and an instance set in a second server render; the production build ships no diagnostic text.
