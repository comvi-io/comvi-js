**BREAKING** — the 0.8 rebuild of `@comvi/core` starts: the message compiler and the locale module are new. Messages use one grammar, ICU MessageFormat as ICU4C reads it: `plural`, `selectordinal`, `select`, `=N`, `offset:` and `#`, with ICU apostrophe quoting, and rich-text tags (`<b>…</b>`, `<br/>`) are always recognized. `#` is the count only in a plural's own sub-messages; inside a `select` nested in a plural it is a literal `#`, as in ICU4C, and development builds warn about it once per key and locale. A plain `{x}` prints numbers, dates and string lists formatted for the locale. `{x, number}`, `{x, date}` and `{x, time}` are not supported: they report a `syntax` error, and the value is formatted in code instead. A message that does not compile renders its key and reports `syntax` instead of throwing. Locales are canonicalized (`en_US` → `en-US`, `iw` → `he`), fall back through a parent chain that never crosses scripts (`zh-HK` never reaches `zh`), and `negotiate()` picks the best supported locale for a list of requested ones. `createI18n` and the instance return in the next step of the rebuild; the 0.7 subpaths (`/icu`, `/loader`, `/plugins`, `/devtools`, `/rich-text`, `/tags`, `/editor-bridge`) and the CDN global build are removed.
