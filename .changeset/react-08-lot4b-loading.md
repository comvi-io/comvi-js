`<I18nProvider loading | suspense>` gates the first paint only while a namespace being loaded has no catalog of any locale (inline `messages` or a fallback locale's catalog show at once), and opens when a render without it COMMITS, so a render React abandons changes nothing. A server render and a hydration always render the children, so an `<I18nHandover>` hydrates at any depth (a Fragment, a layout, a `<Suspense>`) with no mismatch and no request for its payload. `useI18n()` without a namespace activates `default` too, so an app whose `namespaces` option leaves it out loads it on first use instead of showing it as loading forever. `useFormat()` activates no namespace, and relative time counts from a handed-over `serverNow` only in a component's hydration render (a Suspense boundary hydrated later too) and from the browser clock in every other render, a component mounted after the hydration included. With a server payload the order is data → gate → content: the first paint's payload goes to `createI18n({ ...options, ...payload })`, so the gate never waits for it; the provider does not look for a handover inside the subtree it gates, which renders only when the gate opens on a client render (a hydration is never gated).
