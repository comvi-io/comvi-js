# Plan v0.3 — Fix Everything (React Packages)

**Status:** `pending approval` (consensus achieved iter 2 — Architect signed off, Critic APPROVED).
**Source audit:** `AUDIT-react-packages.md` (top-level), `packages/react/AUDIT-FINDINGS.md`, `packages/react/AUDIT-CONCURRENCY.md`.
**Branch:** `chore/react-packages-audit` (or fresh branch off `develop` per branching convention).
**User mandate:** "Fix everything; breaking changes allowed; raise library quality."
**Scope:** `@comvi/core`, `@comvi/react`, `@comvi/next`. Vue/Solid/Svelte/Nuxt migrate against new `@comvi/core@0.3.x` in coordinated follow-up PRs (out of scope here).
**Estimated effort:** ~22-30h across 6 PRs in 4 waves.

---

## Goal

Close every audit finding: **2 P1 + 14 P2 + 8 P3 + 4 ADR open questions = 24 items**. Coordinated `@comvi/*@0.3.0` release line.

## Principles

1. **Evidence-anchored** — each fix cites a finding ID in `AUDIT-react-packages.md`.
2. **Measurement-validated** — each PR has at least one automated gate; manual review only when no machine check exists.
3. **Per-wave atomicity** — each wave is independently revertable.
4. **Hydration invariant preserved** — Wave 2c asserts byte-equivalent `renderToString` pre/post refactor.
5. **Quality framing** — `next/client/I18nProvider` render-mutation removal is a render-purity quality improvement, not a correctness fix (current ref-guard is already idempotent per Architect's review).
6. **Coordinated SemVer where coupled, separate where not** — Wave 2 (2b-i + 2b-ii + 2c) ships in coordinated v0.3.0 line; W1/W2a/W4 independent.

## Decision drivers

1. Close all P0/P1 (correctness)
2. Modernize peers and internals (React 18+ baseline, native APIs, no shim)
3. Eliminate type/style/test debt
4. Single-place verification of "fix everything" closure

### Wave 2b-ii — `@comvi/react@0.3.0-alpha.2` (SemVer-major, architecture, ~8-10h)

Core architectural changes — the bulk of the v0.3 work. Cohesive per Architect's review (the tRaw fix only becomes measurable once cacheRevision is read independently of locale).

**Changes:**

- **2-context split** (B5, OQ-2):
  - `LocaleContext` (string) — Link, usePathname, formatters subscribe here
  - `I18nInstanceContext` ({ i18n, isLoading, isInitializing }) — instance access + loading UX
  - `cacheRevision` is NO LONGER in any context value — `<T>` reads it directly via its own `useSyncExternalStore` (cache subscriber is the only true cache consumer)
- **W1.1 tRaw locale-tearing fix (folded in)** (Dim 6 P2, OQ-1): `useMemo([i18n, ns, locale])` + closure injects locale into `tRaw` calls; `<T>` reads locale from `useLocale()` and passes via `transportParams.locale`
- New additive hooks: `useLocale()`, `useIsLoading()` — exported from `@comvi/react`
- **`React.memo(T)` removal decision (OQ-4)** — gated by:
  - **Primary CI gate (Architect Delta-a):** `render-counts.test.tsx` shows commit count unchanged for 50-`<T>` tree on locale switch
  - **Advisory:** tinybench p50/p99 (≥1000 iters); report attached to PR
  - **Rule:** memo removal allowed iff `render-count identical AND p99 regression < +15%`. If gate fails, keep memo and mark OQ-4 deferred in ADR
- Deprecate `useI18nContext` direct export: `@deprecated` JSDoc; works through v0.3, removed v0.4
- **ADRs published in this PR:** `docs/adr/0001-i18n-locale-source.md`, `0002-context-split.md`, `0004-T-generic-vs-memo.md`

**Acceptance:**

- `render-counts.test.tsx`: Link namespace-load = **1 commit** (was 2); usePathname namespace-load = **1 commit** (was 2); 50-`<T>` locale switch unchanged at **1 commit**
- `tearing.test.tsx` Repros 1 + 2 upgrade indeterminate → **confirmed-sound** (because `<T>` no longer reads `i18n.locale` via closure)
- Tinybench p99 reported in PR description (regression rule above)
- 3 ADR docs published

## Pre-mortem (3 scenarios)

1. **Hydration mismatch under StrictMode** — `useState` initializer fires twice, double-applies messages, server/client cache-revision diverges.
   - **Mitigation:** existing `lastAddedMessagesRef` identity-guard preserved INSIDE the initializer; node-env `renderToString` gate asserts byte-identity pre/post; tests run with StrictMode-ON.

2. **`<T>` per-render slowdown not visible in commit counts** — removing `React.memo(T)` could regress wall-time even if commits identical.
   - **Mitigation:** tinybench advisory gate (p99 < +15%, ≥1000 iters); if exceeded, keep `React.memo` and document OQ-4 as deferred in ADR.

3. **Verification matrix rot** — over time, audit findings get marked closed without actual closure.
   - **Mitigation:** CI lint rule grep-enforces each `artifact` column entry resolves to a file/test ID. CI fails on any unmatched row.

## ADR (audit-level)

### Decision

Approve v0.3 release line per the 4-wave / 6-PR plan. Resolve OQ-1 via the `useMemo([..., locale])` closure injection paired with 2-context split (Alternative 2 from audit ADR). Resolve OQ-2 via 2-context split (LocaleContext + I18nInstanceContext + direct cacheRevision subscription in `<T>`). OQ-3 (Suspense) deferred to Wave 5+. OQ-4 (T memo+generics) decided in W2b-ii by tinybench measurement.

### Drivers

1. Correctness: eliminate render-side-effects, remove tearing surface, fix measured re-render fan-out
2. Quality: modernize peers (React 18+), native APIs, no shim, type debt cleanup, all test-coverage gaps closed
3. Verifiability: single-place "fix everything" closure via verification matrix + CI grep

### Alternatives considered

- **A. Single mega-PR (core + react + next)** — rejected: violates Principle 3 (per-wave atomicity); reviewer fatigue
- **B. 6 PRs in 4 waves** ← chosen
- **C. 3-PR sequential (core → react → next)** — rejected: 3× CI cycles, intermediate broken state for 2 cycles
- **D. (Architect's Option D) Minimal: W1.1 + W1.6 + minimal 2-context, ~10h** — rejected by user "fix everything" mandate

### Why chosen (B)

- Each wave independently revertable; risk-bounded
- Wave 1 lands quick low-risk wins on 0.2.x while v0.3 is built
- Wave 2 splits architecture (2b-ii) from baseline (2b-i) so peer bump is reverted cheaply if needed
- Wave 4's verification matrix + CI grep gives user single-place "fix everything" confidence

### Consequences

- SemVer-major in `@comvi/react@0.3.0` and `@comvi/next@0.3.0`; minor in `@comvi/core@0.3.0`
- Coordinated migration guide
- Vue/Solid/Svelte/Nuxt migrate against new core in their own PRs (out of scope here)
- `useI18nContext` direct consumers receive `@deprecated` warning in v0.3; removed in v0.4

### Follow-ups (Wave 5+ docket)

- React.cloneElement → composition (when React 20 escalates warning)
- Suspense / `use()` integration (OQ-3) — pending product decision
- `useSetLocaleTransition()` (B4) — DX feature
- `useFormatters()` — promote only if W2b-ii measurement creates demand
- Error Boundary documentation
- Vue/Solid/Svelte/Nuxt migration to additive core API
