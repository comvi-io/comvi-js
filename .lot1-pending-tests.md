## Decisions taken in 1b (for the reviewer)

- **Locale spelling.** Catalog keys and loader/CDN requests use the locale as the app spells
  it (`iw` stays `iw`, `pt_BR` stays `pt_BR`); the canonical tag is computed alongside and
  is what Intl gets. A tag that does not canonicalize is `invalid_locale`: `setLocale`
  rejects (RangeError) before any request, `add()` ignores it, a per-call `{ locale }` falls
  back to the instance locale, an invalid start locale renders through its fallbacks. An
  empty per-call locale is "no per-call locale".
- **Fallback chain** = the locale and its script-aware parents (`pt-BR` → `pt`), then each
  `fallbackLocale` entry with its parents. Parents are loaded too. `fallback_used` is
  reported only when a `fallbackLocale` entry answers, not a parent of the locale. A
  fallback message formats for the locale it was written in.
- **Loading.** `setLocale(l)` switches inside the call when nothing has to load; else when
  its loads settle, unless every active namespace failed for `l` itself with no catalog of
  `l`'s own chain in place (`de-AT` 404 with `de` loaded switches; then it rejects with
  that error and stays). A namespace activated by `load()` while the switch is pending is
  loaded for `l` before the switch lands, and the old locale's loads are aborted then.
  Failed pairs are remembered (no refetch on every switch or read) until `setLocale()`
  targets their locale again or `load(ns)` names their namespace. `ready` is one promise
  per set of loads in flight (a shared resolved one when idle) and settles when they do;
  it never rejects (the failures are `load_failed` reports). `load(ns)` never rejects
  either. An aborted flight settles even when the loader ignores its signal. `missing_key`
  is not reported while any load of the namespace is in flight.
- **Plugins** are `{ name, setup(i18n) → teardown? }`, set up in order after the initial
  state, torn down last-first by `destroy()`; a throwing `setup` tears down the earlier ones
  and rethrows (0.7 init-failure-rollback). A plugin may switch the locale in `setup`; the
  initial load then loads that locale only. `detect()` IS a plugin (design §3.3, restored in
  the fix pass): it switches in `setup`, so nothing loads for the `locale` option when a
  source names another supported locale; a detected locale that fails entirely falls back to
  `locale`, which is then loaded. Its options keep the 1b names (`order`, `query`, `key`)
  rather than §3.3's `strategies`/`cookie`, and it has no `fallback` (`locale` is it) —
  a deviation from the §3.3 sketch for the reviewer. `persist()` writes switches back.
- **`@comvi/core/cdn`**: bundled catalogs are `cdn(base, { fallback })` (R3-12; keys `locale`
  and `locale:ns`; network error, non-2xx, bad body, timeout — never an abort);
  `withFallback` is removed. `root: false` = every namespace in its own folder. The timeout
  races the whole request, body included.
- **`@comvi/core/format`** follows §3.3: `formatRelativeTime(i18n, date, now?, options?,
locale?)` picks the unit (`numeric: "auto"`), `now` defaults to the `now` option, then the
  clock; `formatNumber`/`formatDate` take a `formats` entry name. `formatCurrency`,
  `formatDateRange`, `formatList`, `displayName` keep a trailing `locale?` (not in §3.3).
- **Numeric-string counts (owner, R3-12(1), 27.10):** a `plural`/`selectordinal` count that
  is a numeric string (`"5"`, `" 2.5 "`) goes through `Number()` as in 0.7; a blank or
  non-numeric string, `NaN` or a missing value renders `{n}` and reports `missing_param`.
  ICU4C golden rows for numbers are unchanged; the rows marked `coerced` cover the strings.
- **Reserved names:** `ns` and `locale` in `t()`'s params are per-call options; a message
  param of either name cannot be passed (typegen, lot 3).
- **Reporter isolation:** a throwing `onError` never breaks a render or a load; its error is
  rethrown from a `setTimeout`. `defaultParams` and `fallbackLocale` are copied: each
  published state keeps its own `defaultParams`, and `setDefaultParams()` after `destroy()`
  does nothing.
- **A throwing subscriber or teardown** does not stop the others; its error is rethrown from
  a `setTimeout` (0.7 isolated listener failures).
- **Development-only** checks: a non-string catalog value reports `syntax` ("flat"
  catalogs) — the 0.7 flattening is gone; production does not check values.
- **Dev dedupe**: the default reporter prints each (code, key, param) once, a keyless report
  once per (locale, ns); `missing_param` reports carry `param`. The dedupe set is
  process-wide: a development SSR server prints a problem once for all requests (in the
  changeset).
- **Removed 0.7 concepts, not ported:** per-call `fallback` text (`fallback-param-shared-cache`;
  the `missing` hook replaces it), defaultParams' reserved-key / nullish / guaranteed-key
  validation (`default-params`, `audit-default-params`: R3-3 "no validation"), `init()`
  and its single flight / re-run semantics (`initialization`, `init-single-flight`: the
  constructor is synchronous, loads are deduped per pair), `clearMessages` /
  `reloadMessages` / `setDefaultNamespace` (`namespaces`), post-processors.
- **The perf A/B** (`node scripts/perf.mjs --compare-ref origin/next`) reads both core
  generations; it is a release check, not a CI gate.

## Decisions taken in 1c (for the reviewer)

- **Handover is its own component.** `<I18nHandover catalogs locale>` (inside an
  `<I18nProvider>`) holds the S9 commit model: render-local `view(i18n, state, catalogs,
locale)`, `add()` + `setLocale()` in a layout effect, the locale handover as derived state
  keyed on `lrev`. Design §3.4's provider has no handover props, and as a separate export an
  app without a server payload carries none of it (~350 B). `catalogs` has the shape of
  `createI18n({ catalogs })` (namespace → locale → flat). `view()` gained a `locale`
  argument for it.
- **`UntypedT` stays `string`** (documented narrowing). An ungenerated project's `t()` is
  typed `string` so it fits string props (`title`, `placeholder`); a call with a tag
  handler or a node param returns a React element at runtime — use `<T>` (typed
  `ReactNode`) for rich text. With generated catalogs, a key with a `Tag` param is typed
  `ReactElement` from `useI18n().t`.
- **Tag handlers** receive their children as ONE node (a Fragment with varargs), so nested
  tags and element params render with 0 key warnings (React 19 SSR smoke). A handler that
  returns `undefined`/`null` renders nothing, silently (React's own rule). A function passed
  as a plain `{x}` is a rich part, which React refuses with its own development warning and
  renders nothing. A throwing handler throws to the app's error boundary (0.7's per-tag
  boundary class is gone).
- **`loading` / `suspense`** gate on loads of the CURRENT locale only, so a switch keeps the
  old locale on screen and a failed load renders the children (keys, reported) instead of a
  spinner forever. `suspense` throws `i18n.ready` (one promise per set of loads: no
  re-suspend on a re-render; after the loads settle nothing is thrown).
- **`useI18n(ns)`** activates the namespace in an effect (never in render, R4-15);
  `isLoading` is "a load of this namespace for any locale" (a switch in progress included).
  `useLocale()` reads a context of its own that carries only the locale.
- **Development-only diagnostics**: `@comvi/react` ships a `development` build like core;
  "no `<I18nProvider>`" exists only there. `/internal`'s instance check is development-only
  too (−27 B on the React row).
- **0.8 catalogs in the examples are flat**; the shared `examples/locales` moved with them.
- **The client e2e race (step u)** expects the 0.8 behaviour for React and vanilla: the
  superseded switch's request is aborted.
