### Decisions (for the reviewer)

- **Plugin shape.** `createI18n(options)` of `@comvi/vue` is core's `createI18n` plus
  `install` on the instance (design §3.5 `I18n & VuePlugin`): `app.use(i18n)` provides it under
  a module Symbol and sets `$t` on `globalProperties` (typed through
  `ComponentCustomProperties`). React re-exports core's `createI18n` as is; Vue cannot (a Vue
  plugin needs `install`). The reactive cell — one `shallowRef(state)` subscribed with
  `i.on()`, and the `locale` / `dir` `computed` slices — is made with the instance (outside
  any component scope) and kept on it under the same Symbol. Peer `vue ^3.5.0` (computed is
  not bound to an effect scope there).
- **`useI18n(ns?)`** returns design §3.4's seven members, Vue-style: `locale` a
  `WritableComputedRef` (set → `setLocale`, the value stays until the catalogs are in; a
  rejected switch is swallowed — `onError` reported it — so a `v-model` never sees an
  unhandled rejection), `dir` and `isLoading` `ComputedRef`s; `t` reads the whole state
  (§2.5's accepted compromise, as React). Activation of `ns` in `onMounted` (React: an
  effect), never in setup or render; `isLoading` is core's `coming()` like React.
- **`pendingLocale`: in NO binding** (R3-5 all-or-none; parity test `tests/binding-parity`).
  React has no pending target (the core's `State` has none; a provider state for it is a
  re-render and bytes on a binding with 31 B of cap left), a Vue-local ref would miss switches
  that `detect()`, another component or `i18n.setLocale()` start, and `isLoading` already shows
  a switch in flight. Owner may revisit; adding it later is additive.
- **`<T>`.** `i18nKey` is the one declared prop (templates write `i18n-key`); every other
  attribute is a param, `ns` / `locale` / `markers` included (the core reads them off the
  params, as React's props). Tag handlers: an attribute of the tag's name, or a SLOT of that
  name with `{ children }` (an attribute wins). The exported `<T>` is its own module and chunk
  and activates the namespace of its `ns` attribute in a post-flush `watchEffect` (attrs are
  tracked: a new `ns` activates); `useI18n(ns).T` is a FUNCTIONAL component, one per
  namespace for the app's lifetime (prototype-free cache), whose namespace `useI18n(ns)`
  activates. Typed with core's guarded `TComponentFor` / `BoundTFor` with the new slot flag
  (`Tag` params optional: a slot may give the handler); output `VNodeChild`.
- **Joiner and rich output — deviation from React.** A tag's children reach its handler as
  ONE child: their text when they are all text (the usual `<link>terms</link>`, so a slot
  renders `{{ children }}`), else the LIST of their parts (Vue renders an array child as a
  fragment; `h("a", props, c)` takes both). `t()` of a rich message returns the parts list
  (`VNodeArrayChildren`), for render functions; templates use `<T>`. A Fragment VNode (React's
  choice) cost 22 B over the cap and is not needed by Vue. Nested markup inside a tag rendered
  by a template slot needs a handler attribute instead (README says so). `TagChildren` registers
  `vue: string | VNodeArrayChildren` (`Children`, exported). A handler returning
  `null`/`undefined` renders a comment node (Vue's rule); a throwing handler goes to the app's
  `errorHandler`.
- **First paint.** No provider component in Vue: the app mounts after `i18n.ready` (README,
  example: a wordless spinner in `index.html` until `main.ts` mounts) — the same first-paint-only
  semantics as React's `loading`; later loads keep the app on screen.
- **SSR, one instance per request (R3-18(3)).** The app factory creates the instance with the
  app; a development guard throws when one instance is installed into a SECOND app with no
  `document` (a server). A server render activates nothing (no `onMounted`; React parity):
  the request loads its route's namespaces and awaits `ready` before `renderToString`
  (`onServerPrefetch` waiting was built, measured at 25 B, and dropped for the cap).
  `handover(i18n)` — new in `@comvi/core/internal`, re-exported by `@comvi/vue` — returns
  `{ locale, timeZone, now, catalogs }` (active namespaces × the locale's chain, patches
  merged); the browser's `createI18n({ ...options, ...payload })` hydrates with 0 catalog
  requests. Development throws without `timeZone` (R3-5/§2.6: required only for SSR). Vue has
  no render-local `view()`: the payload is in the instance before the app is created, so H9's
  "view() is marked" has nothing to cover (core's own test covers `view()`).
- **Bound `<T>` with a template's spelling**: a functional component with no declared props
  receives the attribute as written, so it reads `i18nKey || "i18n-key"`; the key reaches the
  params too (no message uses it).
- **`useFormat()`** (`@comvi/vue/format`) reads the locale when a formatter is CALLED (a
  reactive read): a template re-renders on a switch only. React binds to the render's locale;
  Vue has no render-local locale, so a formatter kept from earlier formats in the current one.

### API (brief §1)

| API                         | Reads translations | Makes sure it loads         | Keeps the namespace active |
| --------------------------- | ------------------ | --------------------------- | -------------------------- |
| `useI18n(ns)`               | yes                | yes                         | while it has a consumer    |
| `i18n.load(ns)`             | —                  | yes                         | no                         |
| `t()`, `$t()`, `<T>`        | yes                | no (never starts a request) | no                         |
| a namespace of `namespaces` | —                  | at start (the startup load) | always                     |

- `ns` among a call's params only picks the catalog. The exported `<T ns="account">` loads
  nothing, on a server neither. `useI18n("account").T` reads the namespace its `useI18n`
  declared.
- `load(ns)` keeps the 4b rules (rejection, explicit retry of failed pairs) and pins nothing.
- A remount after a failed load asks for nothing (the failed pair stays in the negative
  cache); the explicit retry is `load(ns)`.

### `isReady` / `isLoading` (brief §2) — core predicates, one per field

With `chain(locale)` = the displayed locale, its parents, then the allowed fallback locales and
their parents (what `t()` looks in), for namespace `n` in state `s`:

- **`isReady(s, n)`** = `chain(s.locale).some(([l]) => s.c[n]?.[l])` — a catalog of the
  displayed locale, a parent or an allowed fallback locale is in place (inline, cached, handed
  over or loaded; an empty catalog counts). A catalog of another locale (not in the chain)
  does NOT count. During a switch `s.locale` is the locale on screen, not the target.
- **`isLoading(s, n)`** = a load of `n` is in flight in `s` (any locale: the target of a pending
  switch too) **or** the instance has a loader and a pair `(l, n)` of `chain(s.locale)` is
  neither in place nor failed (in the negative cache) — the load a declared need makes (a
  consumer's hold, which a component's render precedes: React commits, Vue mounts after it).
  A failed pair is a known result: it does not keep `isLoading` true, so no catalog + no
  flight + failed (or no loader) = `false`/`false`, never an endless loading state.

| Situation                                       | `isReady` | `isLoading` |
| ----------------------------------------------- | --------- | ----------- |
| First load, no catalog                          | `false`   | `true`      |
| A catalog of the chain is in place              | `true`    | `false`     |
| A usable catalog, a load in flight              | `true`    | `true`      |
| The load failed, a fallback catalog is in       | `true`    | `false`     |
| No catalog; the load failed, or none is planned | `false`   | `false`     |

The React first-paint gate (`<I18nProvider loading | suspense>`) waits while a namespace with
a load in flight is not `isReady` (the same predicate): a catalog of a locale outside the chain
does not open it (owner's review of e5a3788d, HIGH).

`missing_key` (owner 30.10), one rule for `t()`, `$t()`, the exported and the bound `<T>`: the
key is not found, at least one catalog of the namespace is in place for the read's chain (its
locale, parents, fallback locales), and every pair of that chain is SETTLED — its catalog in
place or its load failed (the negative cache), AND no load of that pair in flight. A pending
request has priority: a catalog `add()`ed to a pair while its request runs does not settle it,
and a retry (`load(ns)`, a switch) that clears a failure and asks again makes the pair unknown
until it finishes. With a loader, a pair never requested or still loading is unknown and keeps
the read silent (no request in flight is not "finished"); without a loader the catalogs in place
are the complete set and are checked at once. Every check uses the namespace and the chain of
the specific read, a per-call `{ locale }` and `{ ns }` included. Reported at the read
with its key, namespace and locale; nothing is replayed when a load lands. A failed load is
`load_failed`. A namespace with no catalog of the read's chain is never a `missing_key`:
development warns (below), production says nothing.

| Situation                                                       | Every surface            |
| --------------------------------------------------------------- | ------------------------ |
| fallback catalog without the key, main locale not requested yet | silent (unknown)         |
| main locale loading                                             | silent                   |
| main locale loaded with the key                                 | the translation          |
| every pair of the chain settled, key absent                     | `missing_key`            |
| no loader, key absent from the catalogs in place                | `missing_key`            |
| no catalog of the chain at all                                  | development warning only |

**Accepted trade-off**: with a loader, a pair nobody ever requests means no production
`missing_key` for its chain (a released namespace after a switch, read against a fallback
catalog; a namespace typo) — an unconfirmed error is not reported.

`i18n.ready` (a Promise) is something else: it settles when the loads in flight at the time of
the read settle, failed or aborted ones too; it says nothing about a namespace's catalog.

### Active set and consumers (brief §3)

```text
active = namespaces of the `namespaces` option (pinned for the instance's life)
       + namespaces with >= 1 consumer (hold count > 0)
```

- Per instance (no module state): a hold count per namespace. A hold (`acquire`, internal)
  counts one consumer and loads what the displayed locale's chain lacks (failed pairs stay
  failed); its release uncounts it. At 0 the namespace leaves the active set: the next
  `setLocale()` does not load it. Release aborts nothing and evicts nothing (the cache stays).
- Several consumers share one catalog and one flight per (locale, namespace).
- React: hold in an effect (commit), release in its cleanup; Vue: hold at mount (on a server,
  in setup: per request), release at unmount; `KeepAlive` deactivation releases, activation
  holds again; mount + first activation hold once. No new public hold/unload API.

### `setLocale(l)` (brief §4)

- At the call: a snapshot of the active set; the loads waited for are those of the snapshot
  (never rebuilt while pending); the locale on screen stays until it applies.
- Applying and rejecting: the 4b rules (own chain, partial failure, latest call wins, a
  superseded call resolves and never switches).
- A namespace released after the call may stay in this call's wait.
- After the switch applies, what the NEW active set lacks for `l` loads (not awaited): a
  consumer that appeared while the switch was pending (it loaded for the locale on screen)
  ends with `l`'s catalog — the active need reacting to the locale change, not a longer
  promise. A switch that rejects loads again what the active set lacks for the locale kept on
  screen (a load its start aborted).

### SSR (brief §5)

- Data → gate → content. Vue: `useI18n(ns)` holds in setup on a server and waits in
  `onServerPrefetch` while the namespace is loading. React: the app preloads (`load()`)
  before `renderToString` (no effects run on a server).
- **SUPERSEDED (30.10, see "SSR with a per-call `{ locale }`" below).** **Handover accounting:** `handover()` hands over every namespace with a catalog of the
  locale's chain in place (an inline one a passive read rendered too: a React server render
  holds nothing, and the browser's `{ ...options, ...payload }` replaces its `catalogs` — fix
  pass, Codex HIGH) and every namespace the instance ever needed — pinned, held, or `load()`ed
  (it never forgets one) — × the locale's chain; a failed pair as `null` (the negative cache,
  not "absent"). It does not read the hold counts, so a released consumer, or `load()` no
  longer pinning, loses no catalog of the payload; the browser keeps the handed-over catalogs
  in its cache (nothing evicts).
- The server render and the first browser render compute the same `isReady`/`isLoading` from
  the same catalogs and failed pairs (`null` slots seed the negative cache), so a
  `v-if`/conditional on them takes the same branch; the hydration requests nothing.

### Decisions (for the reviewer)

- **Vue holds at mount, not in setup** (browser): a setup that never mounts (an error, an async

- **`isLoading` reads the negative cache live** (it is not part of `State`): a render of an older
  snapshot computes "will load" against the current failures; the snapshot's flights still decide

- **The declared-read flag is a development-only seam** (`Core.d`, absent in production): a sixth

### Lot 4b state table (part A: loading and hydration)

Decisions:

- **`t()` of a namespace still loading** returns the missing text (the key, or `missing()`),
  unreported — the same value as a missing key, so there is one "no text" contract; `isLoading`
  is how a component tells the two apart. `""` was rejected: a third output for one lookup,
  and the brief removes the "keys are never visible" promise.
- **`load(ns)`** activates `ns`, asks its failed loads again, and loads what the locale's chain
  lacks; resolves `undefined` (never a boolean: a `false` from vue-router's `beforeEnter`
  cancels the navigation); rejects with the loader's error by the rule of `setLocale()`
  (checked for the locale on screen when the loads settle). A load a switch aborted resolves
  (the switch loads `ns` for its target). A binding's automatic activation (`activate()`,
  React's effect, Vue's `onMounted`/`onServerPrefetch`) never rejects: no unhandled rejection.
- **`setLocale(l)`**: (1) waits for the namespaces active at the call (a snapshot); (2) loads
  what `l`'s chain lacks, the current locale on screen meanwhile; (3) applies only if still
  the latest call; (4) a later call wins and aborts what it does not need; an earlier call
  never switches once a later one exists; (5) a namespace activated while pending loads for
  the locale on screen, then for `l` right after the switch (not awaited); (6) a superseded
  call RESOLVES `undefined` once its loads settle or are aborted (rejecting would turn every
  fast switcher into unhandled rejections), reports only the failures of loads that were not
  aborted; the latest call rejects as in the table; an invalid tag rejects with a
  `RangeError` (production: the message is the tag; `invalid_locale` is reported).
- **Clock** (fix pass: per render, not per instance): `now` is fixed for the instance's life;
  `handover()` emits `serverNow` (was `now`); `clock(i18n, live)` (`@comvi/core/internal`)
  returns it for a render that is not `live`. React `useFormat()` is live except in a server or
  hydration render (`useSyncExternalStore`'s server snapshot — a Suspense boundary hydrated
  later too; React re-renders a hydrated component once, so its time goes live then); Vue's is
  live unless the component hydrates (`vnode.el` is set before its setup — an async component
  hydrated later too) until it has mounted, and never on a server. A component mounted after
  the hydration is live at its first render. Nothing re-renders by itself as time moves.

## Decisions taken in 1b (for the reviewer)

- **Locale spelling.** Catalog keys and loader/CDN requests use the locale as the app spells
  it (`iw` stays `iw`, `pt_BR` stays `pt_BR`); the canonical tag is computed alongside and
  is what Intl gets. A tag that does not canonicalize is `invalid_locale`: `setLocale`
  rejects (RangeError) before any request, `add()` ignores it, a per-call `{ locale }` falls
  back to the instance locale, an invalid start locale renders through its fallbacks. An
  empty per-call locale is "no per-call locale".
- **Fallback chain** = the locale and its script-aware parents (`pt-BR` → `pt`), then each
  `fallbackLocale` entry with its parents. Parents are loaded too. `fallback_used` is
  reported only when a `fallbackLocale` entry answers, not a parent of the locale. A
  fallback message formats for the locale it was written in.
- **Loading.** `setLocale(l)` switches inside the call when nothing has to load; else when
  its loads settle, unless every active namespace failed for `l` itself with no catalog of
  `l`'s own chain in place (`de-AT` 404 with `de` loaded switches; then it rejects with
  that error and stays). A namespace activated by `load()` while the switch is pending is
  loaded for `l` before the switch lands, and the old locale's loads are aborted then.
  Failed pairs are remembered (no refetch on every switch or read) until `setLocale()`
  targets their locale again or `load(ns)` names their namespace. `ready` is one promise
  per set of loads in flight (a shared resolved one when idle) and settles when they do;
  it never rejects (the failures are `load_failed` reports). `load(ns)` never rejects
  either. An aborted flight settles even when the loader ignores its signal. `missing_key`
  is not reported while any load of the namespace is in flight.
- **Plugins** are `{ name, setup(i18n) → teardown? }`, set up in order after the initial
  state, torn down last-first by `destroy()`; a throwing `setup` tears down the earlier ones
  and rethrows (0.7 init-failure-rollback). A plugin may switch the locale in `setup`; the
  initial load then loads that locale only. `detect()` IS a plugin (design §3.3, restored in
  the fix pass): it switches in `setup`, so nothing loads for the `locale` option when a
  source names another supported locale; a detected locale that fails entirely falls back to
  `locale`, which is then loaded. Its options keep the 1b names (`order`, `query`, `key`)
  rather than §3.3's `strategies`/`cookie`, and it has no `fallback` (`locale` is it) —
  a deviation from the §3.3 sketch for the reviewer. `persist()` writes switches back.
- **`@comvi/core/cdn`**: bundled catalogs are `cdn(base, { fallback })` (R3-12; keys `locale`
  and `locale:ns`; network error, non-2xx, bad body, timeout — never an abort);
  `withFallback` is removed. `root: false` = every namespace in its own folder. The timeout
  races the whole request, body included.
- **`@comvi/core/format`** follows §3.3: `formatRelativeTime(i18n, date, now?, options?,
locale?)` picks the unit (`numeric: "auto"`), `now` defaults to the `now` option, then the
  clock; `formatNumber`/`formatDate` take a `formats` entry name. `formatCurrency`,
  `formatDateRange`, `formatList`, `displayName` keep a trailing `locale?` (not in §3.3).
- **Numeric-string counts (owner, R3-12(1), 27.10):** a `plural`/`selectordinal` count that
  is a numeric string (`"5"`, `" 2.5 "`) goes through `Number()` as in 0.7; a blank or
  non-numeric string, `NaN` or a missing value renders `{n}` and reports `missing_param`.
  ICU4C golden rows for numbers are unchanged; the rows marked `coerced` cover the strings.
- **Reserved names:** `ns`, `locale` and (since 1e) `markers` in `t()`'s params are
  per-call options; a message param of any of them cannot be passed (typegen, lot 3).
- **Reporter isolation:** a throwing `onError` never breaks a render or a load; its error is
  rethrown from a `setTimeout`. `defaultParams` and `fallbackLocale` are copied: each
  published state keeps its own `defaultParams`, and `setDefaultParams()` after `destroy()`
  does nothing.
- **A throwing subscriber or teardown** does not stop the others; its error is rethrown from
  a `setTimeout` (0.7 isolated listener failures).
- **Development-only** checks: a non-string catalog value reports `syntax` ("flat"
  catalogs) — the 0.7 flattening is gone; production does not check values.
- **Dev dedupe**: the default reporter prints each (code, key, param) once, a keyless report
  once per (locale, ns); `missing_param` reports carry `param`. The dedupe set is
  process-wide: a development SSR server prints a problem once for all requests (in the
  changeset).
- **Removed 0.7 concepts, not ported:** per-call `fallback` text (`fallback-param-shared-cache`;
  the `missing` hook replaces it), defaultParams' reserved-key / nullish / guaranteed-key
  validation (`default-params`, `audit-default-params`: R3-3 "no validation"), `init()`
  and its single flight / re-run semantics (`initialization`, `init-single-flight`: the
  constructor is synchronous, loads are deduped per pair), `clearMessages` /
  `reloadMessages` / `setDefaultNamespace` (`namespaces`), post-processors.
- **The perf A/B** (`node scripts/perf.mjs --compare-ref origin/next`) reads both core
  generations; it is a release check, not a CI gate.

## Decisions taken in 1c (for the reviewer)

- **Handover is its own component, module and chunk.** `<I18nHandover catalogs locale>`
  (inside an `<I18nProvider>`, `src/handover.ts`) holds the S9 commit model: render-local
  `view(i18n, state, catalogs, locale)`, `add()` in one layout effect and `setLocale()` in
  another keyed on (instance, target) only — a catalogs refresh never undoes a later
  `setLocale()` — and the locale handover as derived state keyed on `lrev`. A target whose
  switch rejects (every catalog of it failed, or an invalid locale) is given up: the subtree
  renders the instance's locale. For a target nobody handed catalogs for, `view()` marks
  what the target's chain lacks of an active namespace as loading, so that render reports
  no `missing_key`. Design §3.4's provider has no handover props; as a separate export in
  its own chunk an app without a server payload carries none of it, its React imports
  included. `catalogs` has the shape of `createI18n({ catalogs })`.
- **Hydration.** The client passes the same `<I18nHandover catalogs locale>` props; a client
  provider with `loading` must start from the server's catalogs (`createI18n({ catalogs })`),
  else its spinner does not match the server HTML (both cases are tests).
- **`UntypedT` stays `string`** (documented narrowing). An ungenerated project's `t()` is
  typed `string` so it fits string props (`title`, `placeholder`); a call with a tag
  handler or a node param returns a React element at runtime — use `<T>` (typed
  `ReactNode`) for rich text. With generated catalogs, a key with a `Tag` param is typed
  `ReactElement` from `useI18n().t`.
- **Untyped params** are `Record<string, object | ReactNode | ((chunks: ReactNode) =>
ReactNode)>` (`UntypedParams`), so an inline handler needs no annotation (the README
  snippet failed with TS7006 before); a `Record<string, unknown>` no longer passes as
  params of the untyped `t`/`<T>`.
- **Bound `<T>` (R3-5(b), R4-20) ships**: `useI18n(ns).T`, one component per namespace for
  the app's lifetime (the context gives the instance), typed by that namespace's keys; it
  fits the cap because the handler wrapping moved into the core (next item).
- **The core joins tag children** (R4-20's joiner): `translate(…, join)` gives every tag
  handler — per-call, `defaultParams`, nested — its children as `join(parts)`; the binding
  passes its Fragment maker. Own-property reads stay in the core, so inherited functions
  are no handlers in React either. Moved bytes: core rows +37 B (core-icu 4,285 B), the
  React increment −53 B.
- **Tag handlers** receive their children as ONE node (a Fragment with varargs), so nested
  tags and element params render with 0 key warnings (React 19 SSR smoke). A handler that
  returns `undefined`/`null` renders nothing, silently (React's own rule). A function passed
  as a plain `{x}` is a rich part, which React refuses with its own development warning and
  renders nothing. A throwing handler throws to the app's error boundary (0.7's per-tag
  boundary class is gone).
- **`loading` / `suspense`** gate the FIRST paint of an instance only (every load in flight
  — the locale's chain and fallbacks), tracked per instance in a module `WeakSet` marked
  during render (idempotent, one-way, publishes nothing). After it, a lazy namespace, a
  retry or a switch never unmounts the app (review 1c BLOCK: the showcase's About page
  reset the app's state); a failed load renders the children (keys, reported).
  `suspense` throws `i18n.ready` (one promise per set of loads: no re-suspend on a
  re-render; after the loads settle nothing is thrown).
- **The context value is memoized** on (instance, state): a parent re-render re-renders no
  memoized consumer and keeps `t`'s identity.
- **`useI18n(ns)`** activates the namespace in an effect (never in render, R4-15) through
  core `activate()`, which does not clear the namespace's failures: a remount after a failed
  load does not refetch (`i18n.load(ns)` is the explicit retry);
  `isLoading` is "a load of this namespace for any locale" (a switch in progress included).
  `useLocale()` reads a context of its own that carries only the locale.
- **Development-only diagnostics**: `@comvi/react` ships a `development` build like core;
  "no `<I18nProvider>`" exists only there. `/internal`'s instance check is development-only
  too (−27 B on the React row).
- **0.8 catalogs in the examples are flat**; the shared `examples/locales` moved with them.
- **The React example is a data router**: the `/about` route's loader awaits
  `i18n.load("account")`, so the page renders with its namespace in place (it used
  `use(i18n.load())` in render before, which publishes during render); pages read the
  shared name through `useOutletContext`. The shared errors-card copy names `onError` and its
  codes; the Vue, Solid, Svelte, Next and Nuxt examples still wire 0.7's hooks and move with
  their lots.
- **`<T>` props**: every prop but `i18nKey` and `ns` is a message param (`children` and
  `className` too; README and JSDoc say so). `<T>` passes its props object as the params,
  so `ns` is read by the core as the per-call option and `i18nKey` is a param no message
  uses.
- **The client e2e race (step u)** expects the 0.8 behaviour for React and vanilla: the
  superseded switch's request is aborted.
